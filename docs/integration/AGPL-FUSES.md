# AGPL 引信清單與自用邊界

> **本文非正式法律意見。所有結論須法務確認後方可據以行動。** 以下為 AGPL-3.0 / GPLv3 的主流讀法方向，供決策參考，不構成背書。

---

## 前提：為什麼純自用可以零開源義務

Shioaji Pro 的前端 repo（shioaji-pro-app）是 **AGPL-3.0**。一旦 fork 並修改它、再把自建的閃電下單 UI 編進這個 fork 的 bundle，該 bundle 整體就是 AGPL 的衍生作品。

但 **copyleft 不是「修改」或「使用」的條件，而是「散布／對外網路服務」的附帶條件**（GPLv3 §2、AGPL §13，須法務確認）：

- GPLv3 §2 授予「製作衍生作品與私下使用」的權利，不附條件。
- AGPL §13 的觸發對象是「**透過網路遠端與之互動的其他使用者**」。

因此在使用者的實際脈絡下——**單人、盤中開著一台機器、不散布、不對外服務、localhost 上唯一的使用者是自己**——**沒有任何開源義務被觸發**：親手寫進 fork 的閃電下單 UI，一行都不用公開，UI IP 完全私有。

> 心法：**只要有「你以外的人」拿到副本，或透過網路用到你的修改版，義務就啟動；你一個人在自己機器上跑，永遠不啟動。**

一個常被誤解的點：一旦決定 fork，AGPL **明文授予完整閱讀與修改其原始碼的權利**。「逆向未知前端」不存在——那只是正常學習一份你合法握有完整 source 的 codebase。

## 六根引信：任一觸發即整包開源義務

以下任一情況發生，義務立刻引爆——需交出**整包 bundle（含使用者自己的 UI）的 Corresponding Source 並以 AGPL-3.0 授權**，或需向永豐（SinoPac）洽商業/雙授權。（均須法務確認。）

| # | 引信 | 性質 | 後果 |
|---|---|---|---|
| 1 | **散布副本給任何人** | convey | 朋友、社群、Email 附一份 bundle、哪怕只給一個人＝散布。整包須以 AGPL-3.0 授權且 source 可取得。 |
| 2 | **公開推上 GitHub** | convey | **最容易誤觸（手滑設 public）**。整包（含使用者 UI）須以 AGPL-3.0 授權、source 公開可取得。詳見下方特別警語。 |
| 3 | **上雲/VPS 讓別人能連進來用**（非 localhost、可多人存取） | §13 網路服務 | §13 全開，**每個遠端使用者**都要被提供 source（現含使用者 UI）。 |
| 4 | **商業化 / SaaS**（讓客戶透過網頁使用） | §13 最強觸發 | 要嘛開源整包，要嘛向**永豐取得 commercial / dual license**。這是任何未來商業計畫的真正殺手。 |
| 5 | **打包成桌面 App（Tauri 等）分發** | convey | 分發二進位＝散布，整包 AGPL 義務引爆。 |
| 6 | **團隊內給哪怕一位同事跑** | convey | 「公司/團隊內部使用」在 AGPL 下仍是 convey——不是「純自用」。 |

**灰區**：只有自己存取的雲端機，嚴格說仍只有自己互動，但任何「可多人連入」的部署都應**視為高風險**——須法務確認。

## 特別警語：公開推 GitHub ＝ 散布 ＝ 最易手滑誤觸

引信 2 值得單獨拉出來反覆強調：

- **一個 `git push` 到 public repo，就是把整包 bundle（含你親手設計、視為私有 IP 的閃電下單 UI）散布出去。** 這一刻，AGPL 的開源義務對整包生效、且**不可逆**——即使事後改回 private，已散布的內容不會收回授權效果。
- fork 一個 AGPL repo 後，remote 常常仍指向或容易一鍵推成 public；**手滑把 visibility 設成 public 是最現實的誤觸途徑**。
- **工程紀律建議**（須自行落實）：fork 一律建 private repo；移除/改寫預設 remote；CI/pre-push hook 檢查 visibility；把「這是 AGPL fork、推 public 即等於開源自己的 UI」寫進 repo README 頂端。

## 自用邊界一句話

**單人、單機、localhost、不散布、不對外服務 → 零開源義務，UI IP 完全私有。**
**只要跨出這條線一步（給任何人副本 / 公開推 / 上雲多人可連 / 商業化 / 打包分發 / 給同事跑）→ 整包（含 UI）AGPL 義務引爆，或需向永豐洽商業授權。**

若現在就預期會跨線，應在動工前改採「以自己前端為底座」的路線以保留專有選項（見 `ADR-001-shioajipro-mount.md` 的硬 gate 與替代方案）。

## 尚須法務確認的項目

1. shioaji Python SDK / shioaji server 工具的**實際授權條款**（公開事實稱其非 AGPL，僅前端 repo 為 AGPL）。
2. 「單機自用不觸發 copyleft」「localhost 單一使用者不落入 §13」的法律判讀。
3. 灰區：只有自己存取的雲端部署是否安全。
4. 未來若商業化，永豐 commercial / dual license 的可得性與條件。
